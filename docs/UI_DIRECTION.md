# UI 방향과 도구 선택

기본 제안은 **Base UI + 제품에 맞춘 디자인 토큰**입니다. Base UI는 스타일이 없는
React 컴포넌트 기반이므로 정보 구조·타이포그래피·여백·표면·모션을 직접 설계할 수
있습니다. 빠르게 일관된 완성형 컴포넌트가 필요하면 **HeroUI v3**를 선택합니다.
어느 쪽이든 기존 프로젝트의 호환성·팀 규칙을 먼저 확인합니다.

| 선택 | 잘 맞는 상황 | 고려할 비용 |
| --- | --- | --- |
| Base UI + 자체 CSS/토큰 | 독자적인 브랜드, 제품 맞춤 대시보드·업무 화면 | 시각 스타일을 직접 설계해야 함 |
| HeroUI v3 | 일관된 기본 스타일과 상태를 빠르게 구성 | 현재 React·Tailwind 요구조건과 테마를 맞춰야 함 |
| React Aria Components | 복잡한 상호작용과 접근성 요구를 자체 디자인으로 구현 | 조합과 스타일 작업 필요 |

현재 하네스는 프레임워크를 설치하지 않습니다. FE 스킬에 이 선택 기준을 넣고,
HeroUI v3 문서용 MCP를 선택형으로 제공합니다. HeroUI Pro의 유료 블록이나
프리미엄 MCP는 포함하지 않습니다.

## 기본 톤앤매너

출발점은 **명료함·정돈됨·반응성**입니다. 기존 브랜드가 있다면 그 언어와 색상부터
따릅니다. 업무 화면에는 조밀하지만 읽기 편한 리스트·테이블을, 탐색 중심 화면에는
충분한 여백과 명확한 정보 단계를 사용합니다. 모든 내용을 같은 카드로 감싸지 않습니다.

- 시선: 제목 → 핵심 상태 → 주요 행동 → 보조 정보 순으로 읽히게 구성합니다.
- 색상: 중립 배경에 의미 있는 강조색을 사용하고 상태를 색상만으로 전달하지 않습니다.
- 형태: 라운드·테두리·그림자 강도를 몇 개의 토큰으로 통일합니다. 과한 유리 효과나
  그라데이션은 제품 목적과 맞을 때만 사용합니다.
- 글자: 제목과 본문의 위계, 줄 길이, 숫자 정렬, 긴 한글 텍스트를 확인합니다.
- 모션: 상태 변경·위치 관계·피드백을 설명하는 짧은 모션을 사용하고 reduced-motion을
  지원합니다. 네트워크 대기를 장식 애니메이션으로 숨기지 않습니다.
- 조작: 중요한 행동은 찾기 쉽게, 보조 행동은 방해되지 않게 둡니다. 키보드 포커스,
  터치 대상, 오류 복구, 빈 결과와 로딩 상태를 완성도 기준에 포함합니다.

## 구현 전에 남길 짧은 디자인 브리프

UI 구현에 앞서 아래 항목을 기존 작업 기록이나 응답에 정리합니다. 화면별 주요 상태와
전환을 간단한 와이어프레임·흐름도·텍스트 개요로 표현하고, 그 설계를 기준으로 구현합니다.
작은 수정은 변경점만 기록하며, 별도 승인 단계를 자동으로 만들지 않습니다.

```text
사용자와 가장 자주 하는 일:
주요 화면 흐름과 핵심 행동:
화면 구성 / 탐색 경로 / 상태 전환:
톤을 설명하는 세 단어:
정보 밀도와 타이포그래피:
라이트·다크의 배경 / 표면 / 텍스트 / 강조 / 위험 색상:
시스템 테마 기본값 / 사용자 선택 / 저장 / 초기 렌더링:
컴포넌트 선택과 이유:
로딩 / 빈 결과 / 오류 / 성공의 표현:
모바일 / 태블릿 / 데스크톱의 배치·내비게이션 변화:
테마별 키보드 / 대비 / 긴 텍스트 / 오버플로 검증:
```

## 다크모드와 반응형 완료 기준

명시된 프로젝트 요구가 다르지 않다면 라이트·다크·시스템 설정을 지원합니다. 기본값은
OS 설정이며 사용자가 고른 테마는 저장합니다. 시스템 모드에서는 OS 변경을 따르고,
저장소를 사용할 수 없는 상황과 SSR·초기 렌더링의 테마 깜빡임도 처리합니다. 이미 테마
제어 기능이 있으면 재사용합니다. 메뉴·모달·차트·입력창까지 의미 기반 색상 토큰을 씁니다.

[토큰 시드](../.agents/skills/harness-frontend/assets/tokens.css)는 `<html>`의
`data-theme="light"` 또는 `data-theme="dark"`로 명시적 선택을 표현하고, 속성을
제거하면 OS 테마를 따릅니다. CSS만으로 사용자 설정 UI나 영속 저장이 구현되지는 않습니다.

모바일에서는 핵심 행동을 유지하며 열을 쌓고, 태블릿과 데스크톱에서는 콘텐츠에 맞춰
정보 밀도를 조절합니다. 표의 가로 스크롤 영역, 내비게이션 전환, 모달 크기, 터치 대상,
긴 한글·확대 화면을 설계에 포함합니다. 기기 이름에만 의존하지 말고 실제 콘텐츠가
깨지는 지점으로 중단점을 정합니다.

검증은 라이트·다크 × 모바일·태블릿·데스크톱 조합으로 확인하고, 테마 선택·새로고침 후
유지·시스템 변경, 키보드 포커스, 주요 상태의 대비와 오버플로를 점검합니다. 브라우저
자동화가 허용되지 않은 환경에서는 수동 확인 절차를 제공하고, 직접 관찰하거나 사용자에게
확인받지 않은 시각적 결과는 미검증으로 남깁니다.

확정된 내용만 프로젝트의 기존 ADR·설계 결정 기록에 남깁니다. 기존 관례가 없으면
`docs/DESIGN_RATIONALE.md`를 사용합니다. 처음 제안한 색이나 레이아웃은 사용자에게
검토받지 않았다면 확정된 브랜드 요구로 표현하지 않습니다.
