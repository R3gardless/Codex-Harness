# Claude CLI 사용자용 Codex 빠른 안내

기존에 프로젝트 지침·계획·수정·검증을 나눠 사용했다면 같은 작업 습관을 유지하면 됩니다.
파일명과 명령은 직접 대응하지 않을 수 있으므로 현재 환경의 `/` 메뉴가 기준입니다.
로컬 확인 버전은 `codex-cli 0.166.0`이며 제공 환경의 버전·기능은 다를 수 있습니다.

| 하고 싶은 일 | Codex에서 사용할 방법 |
| --- | --- |
| 프로젝트 상시 지침 | 루트 또는 하위 폴더의 `AGENTS.md` |
| 재사용 작업 절차 | `.agents/skills/<name>/SKILL.md`, `$harness-…`, `/skills` |
| 시작·현재 상태 확인 | 프로젝트에서 `codex`, `/status` |
| 허용된 모델 확인·선택 | `/model`; 제공된 모델 범위 유지 |
| 먼저 설계 검토 | `/plan` 또는 “수정 전 계획과 검증 기준을 정리해 줘” |
| 변경 확인 | `/diff`, 또는 터미널에서 `git diff` |
| 코드 리뷰 | `/review`; 리뷰는 테스트 실행과 별개 |
| 긴 대화 정리 | 작업 체크포인트 저장 후 `/compact` |
| 세션 재개 | `codex resume`, 최근 세션은 `codex resume --last` |
| MCP 확인 | `/mcp`, 로컬 설정 목록은 `codex mcp list` |

위 명령이 없으면 자연어 요청이나 제공된 메뉴를 사용하세요. `/init`는 지침을 새로
만드는 기능이므로 이 하네스를 설치한 뒤에는 다시 실행할 필요가 없습니다. 모델 이름과
추론 강도는 이 저장소에서 강제하지 않습니다. 권한을 넓히는 옵션도 기본 사용법에 넣지
않았습니다. [공식 명령 안내](https://learn.chatgpt.com/docs/developer-commands).

## 작업 흐름

1. 프로젝트 루트·지침·필수 산출물을 확인하고 입력과 출력 계약을 정리합니다.
2. 모호한 업무 맥락은 사람이 담당자에게 질문하고 답을 전달합니다. 자동 UI 조작 없이도
   Codex가 질문 초안, 요구사항 표, 구현 선택을 도울 수 있습니다.
3. 핵심 흐름 하나를 먼저 실행하고 API·컴포넌트·통합 테스트를 붙입니다.
4. 허용된 미리보기에서 화면을 직접 확인합니다. Codex에는 실제 오류와 관찰 결과만
   전달합니다. 실행 요청 완료와 기능 검증 완료는 다릅니다.
5. 중요한 선택은 `docs/DECISIONS.md`, 진행 상태는 짧은 작업 메모에 남깁니다.
6. 변경을 리뷰하고 실제 검증 결과와 한계를 정리합니다. 독립 답변이 필요한 단계에서는
   AI 도움을 멈추고 본인이 설명합니다.

## 토큰과 시간

처음부터 모든 스킬·MCP·파일을 읽히지 마세요. 확인된 정보는 짧은 메모로 유지하고,
모르는 API만 공식 문서로 찾습니다. 하나의 요청에는 목표·범위·보존 조건·완료 기준을
함께 적으면 재작업을 줄이는 데 도움이 됩니다. 예:

> 목록 API에 페이지네이션을 추가해 줘. 기존 응답 필드는 유지하고 정렬을 안정적으로
> 만들어 줘. 경계값과 권한 테스트를 실행한 뒤 호환성 영향을 설명해 줘.

장기 작업은 “현재 목표 / 결정 / 변경 파일 / 실행한 테스트 / 다음 행동”만 남긴 뒤
필요할 때 압축합니다. 여러 에이전트는 환경과 사용자 지시가 허용하고 독립적인 작업이
있을 때만 고려합니다. 서버를 많이 켜거나 모델을 크게 쓰는 것이 목표는 아닙니다.

테스트를 대신하지 않습니다. 제품에서는 `harness-test`로 도메인 규칙, API 계약,
권한, DB 통합, 주요 UI 상태를 검증하고 실행 명령을 README에 기록하세요.
