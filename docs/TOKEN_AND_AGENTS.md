# 토큰과 에이전트 운영

기본값은 **하나의 주 에이전트 + 필요한 스킬만 로딩**입니다. 작은 수정은 맥락을 이미
가진 에이전트가 끝내는 편이 효율적입니다. 병렬화는 처리 시간을 줄일 수 있지만
입력 문맥 복제·결과 설명·통합 검증 때문에 전체 토큰은 늘어날 수 있습니다.

## 선택 기준

| 상황 | 운영 방식 | 이유 |
| --- | --- | --- |
| 작은 기능, 명확한 버그, 같은 파일을 연속 수정 | 단일 에이전트 | 새 작업자에게 설명하는 비용이 더 큼 |
| 요구사항·API 계약이 아직 변함 | 주 에이전트가 먼저 확정 | 병렬 구현의 재작업·충돌 방지 |
| 구현과 독립적인 공식 문서 조사 | 필요할 때 읽기 전용 조사 작업자 1명 | 좁은 질문·출력으로 분리 가능 |
| API 계약 확정, FE/BE 파일 소유권 분리 가능 | 독립 구현을 선택적으로 병렬화 | 통합 기준이 있을 때만 시간 이득 |
| 보안·권한·회귀 위험이 높은 변경 | 범위를 제한한 읽기 전용 리뷰 | 추가 토큰으로 독립 검토의 가치 확보 |
| 단순 문서·형식 정리 | 기존 에이전트 또는 허용 경량 모델 | 새 에이전트 트리 구성 불필요 |

여러 에이전트의 총비용은 대략 주 작업 + 각 작업자의 입력·출력 + 조율 + 통합·재검증의
합입니다. 병렬 실행 시간과 총 사용량은 따로 봅니다. 공급자의 캐시 정책이나 작업 모델에
따라 실제 비용이 달라지므로 측정 없는 절감률은 주장하지 않습니다.

## 위임할 때 보내는 최소 계약

```text
목적: 이번 작업자가 해결할 한 가지 문제
근거: 필요한 요구사항과 파일 경로만
권한/범위: 읽기 전용 또는 수정 가능한 파일 목록
보존 조건: API, 데이터 형식, 다른 작업자의 파일
완료 기준: 검증 명령 또는 답해야 하는 질문
반환 형식: 결론, 근거 파일:줄, 변경 파일, 실제 테스트, 미확인 사항
통합 담당: 주 에이전트
```

전체 대화나 저장소를 복사하지 않고 관련 맥락만 전달합니다. 런타임이 전체 기록 상속만
지원하면 그 비용을 고려해 단일 에이전트로 유지할 수 있습니다. 작업자는 필요하지 않은
중첩 위임을 하지 않습니다. 파일 소유권과 공통 스키마를 먼저 합의하고, 동일 파일을
여러 작업자가 수정하지 않도록 합니다.

읽기 전용 리뷰에는 의도한 답이나 “여기가 버그다” 같은 결론을 주입하지 말고 요구사항,
변경 범위, 원자료를 줍니다. 주 에이전트는 제안을 근거로 확인한 뒤 통합합니다.
자신의 수정에 대한 자기 검토와 독립 리뷰를 같은 것으로 표현하지 않습니다.

## 문맥 비용 줄이기

- `rg --files`와 좁은 텍스트 검색으로 위치를 찾고 관련 구간만 읽습니다.
- 잠금 파일·생성물·전체 로그를 매번 읽지 않습니다. 오류 앞뒤와 재현 명령을 보존합니다.
- 스킬은 작업에 맞는 것만, 참고 문서는 필요한 항목만 읽습니다. 상시 로딩 문서에
  모든 모드의 상세 절차를 넣지 않습니다.
- MCP도 실제 필요한 서버만 켭니다. 같은 문서를 검색하는 중복 서버와 광범위한
  클라우드 도구 노출을 피하고 필요한 namespace·도구 범위를 씁니다.
- 문서 검색은 라이브러리·버전·질문을 좁힙니다. 확인한 답을 새 파일마다 다시 검색하지 않습니다.
- 모델 전환은 짧고 독립적인 작업에서 이득이 있을 때만 합니다. 장문 배경을 다시
  전달해야 하면 주력 모델을 유지하는 편이 낫습니다.
- 긴 작업은 `WORKLOG.md` 등에 목표·결정·현재 상태·테스트·다음 행동만 남깁니다.
  `/compact` 이후에는 현재 diff와 체크포인트를 대조합니다.

에이전트 수·설명 길이·테스트 횟수에 고정 숫자를 강제하지 않습니다. 새로운 위험이나
변경이 없으면 이미 통과한 검증을 반복하지 않되, 핵심 테스트를 생략해 토큰을 아끼지는
않습니다. 모든 위임은 현재 환경과 사용자의 허용 범위 안에서만 실행합니다.

이 문서는 운영 원칙입니다. 실제 서브 에이전트 API나 기능은 호스트마다 다르므로
현재 제공된 기능을 확인하고, 없는 기능을 임의의 외부 서비스로 대체하지 않습니다.
